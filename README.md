# 图片批处理工作台（img-desk）

同一批图，一次搞定：**批处理**（裁剪·改尺寸·旋转·转格式·压缩·加水印·改名）、**单图处理**、**平台尺寸速查**（50 条，只查不改图）、**图片拼接**、**图片拆分**、**GIF 工具**（视频转 GIF / GIF 压缩）。图片只在你自己电脑/手机上处理，不上传、断网可用。

> **纯本地处理 · 文件不上传 · 断网可用**

## 六个功能

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 图片批处理工作台  [批处理][单图处理][平台尺寸速查][图片拼接][图片拆分][GIF 工具] │
├───────────────┬──────────────────────────┬───────────────────┤
│ ① 图片上传区   │ ② 预览 + 裁剪框           │ ③ 输出            │
│ ② 步骤链/参数  │   处理前 / 处理后 对比     │   体积/打包 ZIP    │
└───────────────┴──────────────────────────┴───────────────────┘
```
**手机也是能用的**：宽度 ≤560px 时自动变单列，顺序是 **上传 → 预览 → 参数 → 输出**（标签栏吸顶、可横向滑，滚到下面也能直接切功能），裁剪框支持手指拖。

> 六个功能的图片**各自独立**（在「批处理」里传的图不会出现在「单图处理」里）—— 每块功能自己传一次，避免"到底在改哪张"的混乱。

### ① 批处理 ★ 主体

上传多张（拖进来 / 点选 / `Ctrl+V` 粘贴）→ 打开你要的步骤、调参数、用 ↑↓ 排顺序 → 一键跑完打包成 **ZIP**。

| 步骤 | 参数 |
|---|---|
| **裁剪** | ① **画布上可拖拽的裁剪框**（拖框内=移动，拖 8 个小方块=缩放）② **四周均匀裁掉 N 像素**（填百分比或像素）③ 8 档比例（原图 / 1:1 / 3:4 / 4:3 / 16:9 / 9:16 / 21:9 / 自定义宽高）④ 居中 / 重置 / **覆盖全部** ⑤「每张图单独裁」 |
| **改尺寸** | **5 种方式**：按长边 / 按短边 / 指定宽 × 高 / 按百分比 / 装在框内 + **重采样质量**（高/中/快）+「不放大」 |
| **旋转翻转** | 转 90° 的整数倍（顺 90°/180°/顺 270°）+ **任意角度**（-180°~180°）+ **空白处底色** + 水平/垂直翻转 |
| **加水印** | 文字或图片、**九宫格 9 个位置**、字号/大小、颜色、透明度、旋转、边距、**平铺** |
| **转格式** | **保持原格式** / JPG / PNG / WebP + 画质 + **透明图转 JPG 时透明处补底色**（开关 + 颜色） |
| **压缩** | 按画质（滑杆）或 **按目标体积**（填 KB，自动在画质上二分） |
| **改名** | 前缀 + **后缀** + 起始号 + 位数（旁边实时显示示例） |

- 开关关掉的步骤会被跳过；**顺序就是你排的顺序**（先裁再缩，和先缩再裁结果不一样）
- 预览用队列里**第 1 张**跑一遍链，显示 `输出尺寸 · 体积 · 格式`
- 完事出 **ZIP**，里面有进度和"完成 N 张"

#### 裁剪框怎么用

裁剪框画在**右边预览的下方**，直接在上面拖：

- **拖框内** = 移动（只夹回画面，不会改变框的大小）
- **拖四边 / 四角那 8 个小方块** = 缩放（框外自动变暗，框内有一横一竖两条三分线）
- **比例锁**：选了 1:1 / 16:9 之类，框会锁在这个比例上，怎么拖都不会变形、也不会跑出画面
- **切比例时**框会自动变成"这张图里该比例的最大块"（选 1:1 就给你最大的正方形）
- **居中 / 重置**：把框摆回中间 / 恢复成整套比例的最大块
- **覆盖全部**：把当前这张的框套给队列里所有图

**「每张图单独裁」的准确语义**：

| 状态 | 含义 |
|---|---|
| **不勾**（默认） | 全队列**用同一份框**。因为是"占该比例最大块的多少"的表达方式（`frac` 语义），所以每张图会**各自**取自己的最大块 —— 1200×800 和 800×800 都会得到各自的居中正方形 |
| **勾上** | 每张图用**自己拖出来的显式框**，互不影响（适合一张张精调） |

**GIF 会被按首帧处理**（动图变静态图）：缩略图上标「GIF·首帧」，队列、预览、完成日志三处都会提醒 —— 不会静默变静态。想要动图请用专门的 GIF 工具。

### ② 单图处理

一张图 → 预览里**拖框裁剪**（和批处理**同一个裁剪框**、同一套几何）：

- 拖**框内** = 移动；拖**四边/四角** = 缩放；框外自动变暗，带三分线
- 8 档比例（含自定义宽高比），切比例时框自动变成"这张图里最大的同比例块"
- 左转/右转 90°、**任意角度**、**空白处底色**、水平/垂直翻转
- 输出尺寸：跟裁剪框，或指定宽高（可锁比例）
- 导出 JPG / PNG / WebP + 画质

### ③ 平台尺寸速查

**9 个平台 · 50 条常用尺寸**（公众号 / 小红书 / 抖音 / 视频号 / B 站 / 知乎 / 微博 / 头条 / 淘宝），内嵌在页面里，不联网。

**这一块只查尺寸，不动图**（要裁图去「批处理」或「单图处理」）：

- 搜索框按 **平台名 / 用途 / 尺寸数字 / 比例** 过滤，也可以点平台胶囊筛选
- 点任意一行 → 右侧读出该条的 **平台 · 用途 · 宽×高 · 比例 · 注意事项**
- 想按这个尺寸裁图：在「批处理」的裁剪步骤里把比例选成对应比例即可（点一下是那个比例的最大块）

### ④ 图片拼接

多张图拼成一张：竖向 / 横向 / 网格（2×2、3×3、2 行 3 列、3 行 2 列）。

- 队列里可 **← 前移 / 后移 → / 删除这张**，也能一键清空
- 每张可单独设 **跟第 1 张 / 1:1 / 4:3 / 3:4 / 16:9 / 9:16**，摆放方式 **铺满并裁剪 / 完整显示留白 / 统一边长**
- 外观（间距、外边距、底色、圆角、描边）、清晰度 **普通 1× / 高清 1.5× / 超清 2×**、输出 **PNG / JPG**
- 右栏实时预览 + **导出这一张**

### ⑤ 图片拆分

一张长图切成多张：**网格切分**（3×3、2×2、3 行 2 列、3 行 1 列、1 行 4 列）、**长图按段数**、**长图按每段高度**、**自定义分割线**。

- 可加 / 清空分割线，也能按 **原图 / 1:1 / 4:3 / 16:9** 定切片比例
- 预览里每片单独可见 → **打包全部切片（ZIP）** 或 **只下载第 1 片**

### ⑥ GIF 工具

两块并排，互不遮挡：

- **视频转 GIF**：拖入视频（MP4 / WebM / MOV / AVI）→ 设 **开始时间 / 时长 / 帧率 / 宽度 / 颜色数** → 生成 GIF；转完可直接 **去压缩**
- **GIF 压缩**：拖入 GIF → 设宽度 / 颜色数 / 目标体积 → 压缩，并显示 **压缩前 → 压缩后** 的体积与比例

> 和「批处理」里的 GIF 不同：那里是一律**取首帧**当静态图，这里出的是**真动图**。

## 已知限制（如实说明）

- **GIF 只取首帧**（见上）。
- 批处理**不做字节级无损透传**：所有输出都重新编码一次，所以"什么都不改"的图也会被重编码（这是为了保证步骤链顺序可变）；要绝对无损请用原始文件。
- **PNG 没有画质旋钮**，所以「按目标体积」压缩只对 JPG/WebP 有效；选 PNG 时会忽略目标体积（页面会说明）。
- 目标体积压不到时会**如实告诉你实际体积**（画质有下限 40，再低就没法看了）。
- **压缩不会把文件压大**：如果这一遍只做了压缩/改名、格式和尺寸都没变，而重编码反而更大，
  就**原样保留原文件**（和 img-compress 的「只有确实变小才替换」一致）——12 KB 的调色板 PNG 不会再被压成 46 KB。
- 图片解码用浏览器自己的能力：**苹果 HEIC 不行**（会提示），超大图受浏览器画布上限限制。
- **裁剪框默认是满框**（整张图）。满框没有移动余地 —— 想移动请先拖手柄缩小，再拖框内。

## 隐私

- 没有任何外部请求：不开 CDN、不加载字体、不上报数据。
- 图片**只在你自己浏览器内存里**处理，不上传任何服务器。
- 参数存在 `localStorage`，**不存图片**。

| `_core.js` | 纯函数：步骤链模型、参数默认值与上下限（照 img-batch 全套）、平台派生数据、文件名、体积换算、引擎参数翻译 |
| `_app.js` | 应用层：三套队列、七张步骤卡、画布绘制、批量跑链、ZIP、平台表格 |
| `_shell.html` | 页面骨架：CSS + DOM + 占位符 |
| `build.mjs` | 拼装 + 产物自检（不通过就不写文件） |
| `selfcheck.mjs` / `smoke.mjs` / `verify-output.py` | 三份自检（静态+纯函数 / 假 DOM 端到端 / Python 独立解 ZIP 复检） |
| `mutate.mjs` | 变异测试：故意改坏源文件再重建，确认上面三个脚本**真的会报错** |
| `layout-check.cjs` | 真浏览器验收（手机 375 无横向溢出、触摸拖框、真下载 ZIP） |

```bash
cd ..\3-开发脚本
node extract.mjs       # 老工具 → _parts\（老工具改了才需要重跑）
node build.mjs         # → 0-repo\index.html
node selfcheck.mjs && node smoke.mjs && python verify-output.py
node mutate.mjs        # 断言有效性自证
node layout-check.cjs  # 真浏览器（需要 playwright-core）
```

几个刻意的设计：

- **只搬一份引擎**：`img-compress` / `batch-watermark` / `img-crop` 的算法在 `img-batch` 里已经合并过一遍，再各搬一份就会出现三个同名 `drawWatermark`，谁覆盖谁说不清。
- **步骤链自己写**：`img-batch` 的 `renderPipeline` 把顺序写死了（裁→转→缩→水印），而本工具的步骤**用户可排序**，所以只搬"叶子能力"（解码/画布/编码/二分/水印绘制/裁剪几何），编排是本工具自己的。
- **裁剪框只有一个实现**：`makeCropEditor()` 被批处理预览和单图处理各实例化一次；两边的 `cropRect` 调用也完全相同（`singleRect()` 就是 `cropRect`），所以"批处理里看到的裁剪"和"单图处理里裁出来的"必然一致。
- **移动只夹边界、不重算尺寸**：移动时若顺手调 `fitBoxToRatio`，框会被顶成"该比例最大块"——拖一下框就变大（踩过，冒烟断言钉住）。
- **`frac` 语义**：`maxBoxForRatio()` 返回的是"占该比例最大块的多少"，不是像素框。所以"1:1 + 覆盖全部"在 1200×800 与 800×800 上各自得到居中正方形；用户一旦自己拖框，`frac` 丢掉、变成显式框。
- **预览与导出共用 `reencode()` + `encodePlanOf()` + `encodeCanvas()`**：否则"预览好看、导出不对"这种 bug 永远抓不到（变异测试里有一条专门盯这个）。
- **假画布的字节里带尺寸头**：冒烟跑出来的 ZIP 里每个文件都以 `IMGDESK 400x400 image/jpeg q=60|` 开头，于是 Python 能**独立**从 ZIP 里读出真实输出尺寸来验证（不是靠 JS 自说自话）。
- **UI 相关的自检断言一律落在最终渲染的 DOM/CSS 属性上**（`getBoundingClientRect()` / `el.style.width`），而不是内部状态对象 —— "状态对、画面错"这类 bug 只有前者抓得到。
